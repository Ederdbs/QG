Appendix B — The hybdiv package

Every function used in this book lives in one package, whose source is the R/ directory of this repository. This appendix is the index.

#> exported_objects 
#>              193

B.1 Installation

install.packages(c("DEoptim", "quadprog"))
devtools::install(".")        # from the repository root
library(hybdiv)

Only DEoptim is a hard dependency, used solely by sel_de(). quadprog is suggested and needed only for optimal_contributions() and ocs_quadprog(). Everything else, including every plot, is base R.

B.3 The two-stage contract

Everything downstream of stage 1 talks only through three objects. This is the seam for swapping in real data.

st1 <- stage1_simulate()                 # or stage1_build(X, ped, traits, fL)
#   $X        N x m hybrid markers, 0/0.5/1
#   $f        N x N molecular coancestry
#   $hybrids  N x (3 + n_traits): id, line_A, line_B, traits
#   $fL       L x L line coancestry (optional)

res <- stage2_select(st1$X, st1$f, st1$hybrids, n_sel = 100, fL = st1$fL)
#   $selection  0/1 column per scenario, plus n_scenarios
#   $metrics    one row per scenario
#   $z_scores   each metric in s.d. from the random null
#   $ref        gd_ref, its Monte Carlo s.e., alpha_max, n_sel

B.4 Function index

B.4.1 Simulation and context

Function Does
sim_config simulation scale: lines per pool, markers, traits, divergence
simulate_lines() Balding-Nichols line genotypes in two divergent pools
simulate_data() lines, all A x B crosses, both matrices, predicted traits
simulate_pools() lighter simulator returning raw pieces, with GL in 0/1
build_ctx() assemble the context; freezes p0 and the index
build_ctx_from_stage1() same, from the stage-1 contract
ctx_from_pools() context from simulate_pools(), carrying parents and GL
load_data() the single swap point for real data
stage1_simulate() / stage1_build() produce the stage-1 contract
stage2_select() the whole constrained selection pipeline

B.4.2 The two matrices

Function Does
molecular_coancestry() the diversity kernel; one tcrossprod, stays in [0, 1]
vanraden_G() prediction only; sum(G) == 0 by construction
mrd_matrix() / coancestry_from_mrd() modified Rogers distance, the same statistic

B.4.3 Diversity metrics – all f(idx, ctx) -> scalar

Function Does
theta_group() group coancestry, diagonal included
gene_diversity() / he_nei() 1 - theta; the same quantity, two routes
theta_from_freq() theta via allele frequencies – validation only, ~100x slower
status_number() Ns = 1/(2 theta); a static descriptor
ne_parents() effective number of parent lines; independent of f
ne_lines_pool() the same, per pool; needs only the pedigree
alleles_lost() markers polymorphic in the pool, rare in the selection
freq_metrics() one marker sweep: He, F_hom, F_drift, cov_diag, rare_retained
line_weights() / theta_pools() per-pool usage weights and coancestries
gd_partition() Caballero & Toro Eq. 8 over the heterotic pools
ene() / ane() Core Hunter entry- and accession-to-nearest-entry
eff_dim() effective dimensionality, on the double-centered submatrix
gst() Nei’s Gst, selected against non-selected
mean_offdiag() the common production metric, kept for comparison
metrics_cheap() / metrics_full() the inner-loop panel and the post-hoc panel

B.4.4 The fast line route

Function Does
fast_ctx() add parents, GL and the packed bitset to a context
line_counts() / line_usage_freq() the sufficient statistic
fast_theta() / fast_gene_div() / fast_status_num() theta = w' fL w; no N x N matrix
make_theta_fun() precompiled closure for ~1e6 evaluations
theta_state() / theta_swap() O(L) incremental update per swap
fast_ne_parents() / ne_parents_from_counts() free once the counts exist
fast_pbar() / fast_he_nei() / fast_alleles_lost() frequencies from the line matrix
pack_lines() / popcount32() / alleles_retained_fast() bitset allelic richness
fast_theta_pools() pool decomposition from the same counts
decode_rank() / decode_lines() the two encodings; use decode_lines()
make_fitness_fast() DE fitness with several simultaneous restrictions

B.4.5 Selection strategies

Function Does
sel_random() the null strategy
sel_truncation() ceiling on gain, floor on diversity
sel_truncation_cap() per-line cap; no matrix needed, usually most of the benefit
sel_greedy() incremental greedy; w = 0 is max diversity
decode() / make_fitness() / sel_de() differential evolution, warm-started by default
project_capped_simplex() / ocs_relaxation() the continuous upper bound
optimal_contributions() / ocs_quadprog() quadratic-programming OCS

B.4.6 Benchmarking

Function Does
null_distribution() the correct baseline: random subsets of the same size
alpha_loss() proportional diversity loss against that baseline
evaluate() / discriminatory_power() metric panel and its z-scores
cost_per_eval() microseconds per metric; decides what goes inside the loop
plot_null() / plot_correlation() / plot_frontier() base-R diagnostics; run by inst/scripts/run_benchmark.R, not by the book

B.5 Runnable scripts

The book runs everything at a reduced scale so it renders quickly. Three scripts ship with the package and run the same work at the production scale of sim_config, writing their tables and plots to report/:

Rscript inst/scripts/run_all.R          # the two-stage pipeline, ~4 min
Rscript inst/scripts/run_benchmark.R    # the metrics benchmark, ~6 min
Rscript inst/scripts/run_mabc.R         # the MABC scans, ~3 min

run_benchmark.R is the source of the numeric results quoted in README.md, and the only place the three plot_* helpers above are exercised. From an installed copy of the package:

source(system.file("scripts", "run_all.R", package = "hybdiv"))
